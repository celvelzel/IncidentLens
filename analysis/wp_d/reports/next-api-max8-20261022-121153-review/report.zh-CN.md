主口径遵循2026-10-21下轮设计：**分析正常完成运行的质量，技术失败另列为日志事实**。分母随各组实际完成病例变化，不用这些比率证明端到端可靠性或直接排名。

## 4. 技术失败与终止分类异常

原始11个failed槽位保留为：

- 6次 `UNKNOWN_PROVIDER_ERROR` / `PROVIDER_TRANSPORT_ERROR`：slot-020、022、026、028、035、039。错误经过清理，现有日志不足以定位底层网络原因；不能直接都称为超时或限流。
- 1次明确HTTP429 `RATE_LIMITED`：slot-010，达到第3次物理尝试仍失败。
- 2次 `SCHEMA_VALIDATION_FAILED`：slot-004、032，结构修复后仍不符合要求，属于输出协议失败。
- 2次保存为 `BUDGET_EXHAUSTED`：slot-001、012，存在分类异常，不能解释为实际触及实验上限。

### 两条预算失败的具体问题

slot-001使用6/8轮、21/40工具、29/64请求、约877/7200秒；slot-012使用1/8轮、7/40工具、8/64请求、约243/7200秒。两条trace没有RUNTIME_ERROR，最后决策均为ABSTAIN。slot-001的停止理由写“within budget”，slot-012写“Investigation budget exhausted”，STOP逻辑在 `src/incident_lens/orchestration/graph.py:1448` 仅检查自由文本包含 `budget` 就将其归为预算失败。

因此，这两条是**终止分类依赖自由文本的缺陷证据**，并非增加8轮/40工具/64请求上限即可解决的证据。本报告保留11个failed的原始账本与29个完成的主分析分母，没有覆盖结果或私自改记成功。这两例均在参考标为可诊断的病例上未输出根因，即使未来更正为正常弃权，也不会增加本批根因匹配数。

## 5. 引用语义与预期判断

机器规范化检查中，全部结果55/55个去重引用（每个运行内去重后求和）来自本次有效工具观测；正常完成结果为45/45。这个结果说明引用存在并被实际获取，不代表语义完全支持、所有角色ACL经过独立复核，或已完成人工Grounded RCA审核。

对4个匹配诊断的原始记录进行了本报告作者的静态语义检查：

- 3004两条诊断均有池上限20→2的配置差异、153个pool_waiters以及稍后gateway5xx支持主体机制。NoVerifier还用09:00:00的正常backend延迟反驳09:00:27起的资源饱和，这个时点早于故障，不能充分排除后续资源问题：竞争假设排除评为MIXED。
- 3005/Single有155连接超过100容量上限的记录，并有后续deadline与gateway错误，主体机制有支持；报告没有列出被拒绝假设，不能自动宣布竞争假设排除充分。
- 3010/Full有7700ms、CPU等待的数据库样本与对应查询延迟指标，主体慢查询机制有支持；它同时把故障前backend40ms列入链，停止理由称服务层症状coincident，未观察到backend延迟从40ms上升的时间序列，传播链完整性评为MIXED。
