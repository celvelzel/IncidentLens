## 3. 逐案观察

- **3001 / 3006（普通）**：三方完成均弃答，无架构找到根因；NoVerifier 耗时与请求均为同案最高（35.1m/38rq、15.1m/24rq）。
- **3002 / 3007（误导变更）**：Full 在 3007 完成但弃答（29.2m/30rq/22t），在 3002 被排除；Single 在 3007 被排除。误导案例无任何架构命中根因。
- **3003 / 3008（证据缺失）**：Full/Single/Fixed 全部正确弃权——这是全批最一致的正向行为；NoVerifier 两案均因 429 类传输错误被排除，无法评估。
- **3004（反事实A）**：Single 与 NoVerifier 均输出根因（NoVerifier 用 23 请求/15 工具，约为 Single 的 1.8 倍资源）；Fixed 弃答、Full 被排除。
- **3005（反事实B）**：**唯一四架构全部完成的案例**。Single 唯一命中根因（24.4m/30rq/21t）；Fixed 以 2.1m/11rq/7t 弃答——成本最低但未诊断。
- **3009（反事实A）**：三方完成均弃答，无人命中锁等待根因。
- **3010（反事实B）**：Full 唯一命中（15.1m/22rq/18t）；Single 与 NoVerifier 被排除（后者为分类缺陷边缘案例※）。

## 4. 边界

- 本批 `formal=false`、`development_visible`、每组合仅 1 次重复，且四组的技术失败构成不同（Fixed 0 / Single 2 / NoVerifier 3 / Full 5）。完成案例的分母不同，上述对比为描述性汇总，**不构成**因果、效率排名或统计显著性结论。
- 排除的 10 个槽位消耗仍计入批次总账（见上一份汇总第 3 节），此处只是不参与个案对比。
- 耗时取自各 attempt 自身的 `status.json` 起止时间；并发 8 下壁钟时间存在重叠，不代表串行总时长。
