# IncidentLens 本地网关完整 WP-D 四架构对比报告

## 核心结论：多 Agent 优势分析

### Dynamic（无 Verifier）相对 Single

Dynamic 与 Single 的质量均为 10/10：两者都是可识别 8/8 正确、不可识别 2/2 正确弃答。Dynamic 同时降低：

- 平均耗时：391.2s → 233.5s（-40.3%）
- 平均请求：17.6 → 14.0（-20.5%）
- 平均工具：15.0 → 11.8（-21.3%）
- 平均 Token：257,146 → 145,035（-43.6%）

因此，本批最明确的多 Agent 优势是 **Dynamic 在质量不降的前提下降低资源使用**。这是开发集上的描述性结果，尚不等于统计显著结论。

### Full 相对 Single

Full 与 Single 同样为 10/10 质量，但最终成功结果的四项平均资源均更高：

- 耗时：391.2s → 438.9s（+12.2%）
- 请求：17.6 → 18.8（+6.8%）
- 工具：15.0 → 15.9（+6.0%）
- Token：257,146 → 269,832（+4.9%）

把 Full/3010 的重试也算入，全部已知 Token 为 2,877,375（相对 Single 总 Token +11.9%），全部已知耗时为 4612.5s（相对 Single +17.9%）。**本批没有证据支持 Full 比 Single 更正确，也没有资源效率优势。**

### Fixed-4 相对 Single

Fixed-4 最便宜、最快：

- 耗时：-75.2%
- 请求：-55.1%
- 工具：-49.3%
- Token：-78.0%

但它在 `incident_3004`、`incident_3005`、`incident_3010` 三个可识别案例上错误弃答，质量从 10/10 降到 7/10。因此它适合作为低成本对照，不能仅凭资源指标宣称优于其他架构。

### Full 相对 Dynamic

Full 与 Dynamic 质量同为 10/10，但 Full 平均耗时、请求、工具和 Token 分别比 Dynamic 高 +88.0% / +34.3% / +34.7% / +86.0%。在这 10 个开发案例上，独立 Verifier/Full 流程没有带来额外质量收益，却增加了成本。

## 实验与交付状态

- 分支与源码：当前 `main`，提交 `1e222001ccf32bfba4afe0edae7780c5b5e6a4c6`。
- 模型提供商：本地网关 `http://127.0.0.1:3425/v1`；模型 `auto/deepseek-v4.1-flash`。
- 协议：10 个 Dev 案例 × 4 个架构 = 40 个 slot；并发 `4`；temperature `0.0`；cache `off`；单次重复。
- 最终批次状态：`batch_finished`。40/40 个最终 slot 技术完成，最终失败 0。
- 仅 `Full / incident_3010` 发生重试：Attempt 1 因提供商结构化输出错误失败；Attempt 2 因运行终端/监督进程断连被标记为 interrupted；Attempt 3 正常完成。
- 所有 40 个最终成功 slot 均纳入下表；失败尝试不伪装成最终结果，但重试时间和 Token 单独计入“全尝试成本”。

正确性口径：可识别案例要求 `culprit_service` 与 `failure_mode` 同时精确匹配；不可识别案例要求正常完成并弃答。本批 oracle 为 `pending/candidate-v1`，因此“正确”是候选真值口径下的暂定评分。案例均为开发可见的 Dev10，不能据此宣称独立盲测、统计显著或生产泛化。

## 逐案例分析

- **incident_3001**：四方均答对。Fixed-4 最省资源；Dynamic 相对 Single 的耗时、请求、工具和 Token 分别变化 -45.2% / -38.9% / -42.9% / -60.1%；Full 的耗时为 +17.4%，请求、工具和 Token 均下降。
- **incident_3002**：四方均答对。Fixed-4 与 Dynamic 明显更省；Full 的耗时相对 Single 为 -26.6%，但请求、工具和 Token 分别增加 11.1% / 7.7% / 6.5%。
- **incident_3003**：四方均正确弃答。Fixed-4 成本最低；Full 的耗时相对 Single 为 -16.7%，但请求和工具分别增加 4.0% / 8.7%，Token 下降 18.8%。
- **incident_3004**：Fixed-4 错误弃答，Single、Dynamic、Full 正确根因。Dynamic 的四项资源指标均低于 Single；Full 的耗时和 Token 略低，但请求与工具更多。
- **incident_3005**：Fixed-4 错误弃答，其余三方正确根因。Dynamic 四项资源指标均低于 Single；Full 相对 Single 的耗时、请求、工具和 Token 分别增加 26.5% / 20.0% / 6.7% / 15.0%。

## 结论与限制

1. **技术完成与质量正确必须分开**：40/40 技术完成，但质量成功为 Single 10/10、Fixed-4 7/10、Dynamic 10/10、Full 10/10。
2. **Dynamic 是本批最支持的多 Agent 方案**：质量与 Single/Full 相同，同时平均耗时、请求、工具和 Token 全面下降。
3. **Full 未证明优势**：最终成功结果和全尝试成本都不优于 Single；Full/3010 的提供商结构化失败与终端断连分别导致两次额外尝试。
4. **Fixed-4 只证明低成本**：它最快、最省，但在三个可识别案例上错误弃答，不能作为质量最优架构。
5. 本批只有 10 个开发可见案例、每案例单次重复，且 oracle 仍为候选状态；这些结果只能支持开发集上的描述性结论，不能作为统计显著性、独立盲测或生产部署结论。
